# Гипотезы для валидации сервиса RuPrime

## Общие сведения

**Цель:** показать, что сервис выполняет заявленные функции — корректно оценивает навыки игрока, определяет слабые места, подбирает тренера и помогает принимать решения.

**Подход:** каждая гипотеза сопровождается:
- Формулировкой H₀ (нулевая) и H₁ (альтернативная)
- Метрикой проверки
- Источником данных
- Ссылкой на блокнот (ipynb) для воспроизводимости
- Кратким выводом

---

## H0. Качество фичей и дифференциация по рангам

### Формулировка

- **H₀:** Эталоны (baselines) для разных MMR-бэндов статистически не отличаются
- **H₁:** Эталоны для разных MMR-бэндов статистически значимо различаются, что подтверждает осмысленность ранговой системы

### Метрика

- ANOVA F-test по ключевым метрикам (GPM, XPM, KDA, last_hits, hero_damage) между 8 MMR-бэндами
- Post-hoc Tukey HSD для попарных сравнений
- Effect size (η² — eta squared)
- Монотонность: для каждой метрики проверяется, растёт ли среднее с рангом

### Подгипотезы

| ID | Гипотеза | Критерий |
|----|----------|----------|
| H0.1 | GPM монотонно растёт с рангом | Корреляция Спирмена ρ > 0.8, p < 0.05 |
| H0.2 | XPM монотонно растёт с рангом | Корреляция Спирмена ρ > 0.8, p < 0.05 |
| H0.3 | KDA монотонно растёт с рангом | Корреляция Спирмена ρ > 0.7, p < 0.05 |
| H0.4 | Deaths НЕ сильно зависит от ранга | ρ < 0.3 (про-игроки умирают одинаково) |
| H0.5 | Tower Damage значимо растёт | F-test p < 0.05, η² > 0.02 |

### Источник данных

- Таблица `ml_kaggle_baselines` (1389 конфигураций)
- Таблица `ml_raw_players` (594K записей)

### Блокнот

→ `notebooks/H0_feature_quality.ipynb`

### Ожидаемый вывод

Если H₁ подтверждается: система корректно дифференцирует игроков разных рангов и эталоны осмысленны.

## H1. Валидация определения слабых мест экспертом

### Формулировка

- **H₀:** Определение слабых мест алгоритмом не совпадает с экспертной оценкой (случайное совпадение)
- **H₁:** Алгоритм определяет слабые места с точностью ≥ 60%, совпадающей с экспертной оценкой

### Метрика

- **Cohen's Kappa (κ):** межэкспертная согласованность между алгоритмом и экспертом
  - κ < 0.2: случайное совпадение
  - κ 0.2–0.4: слабое согласие
  - κ 0.4–0.6: умеренное согласие
  - κ > 0.6: хорошее согласие
- **Precision / Recall** по каждой категории слабых мест
- **Top-3 overlap:** совпадение топ-3 слабых мест алгоритма и эксперта

### Протокол

1. Выбрать 5–10 игроков разных рангов (Herald–Divine)
2. Для каждого: алгоритм выдаёт список слабых мест (score, gap)
3. Эксперт (тренер с 4000+ MMR) **независимо** оценивает те же данные
4. Сравнить: Cohen's Kappa, Precision, Recall, Top-3 overlap

### Источник данных

- Данные привязанных игроков (`player_accounts`, `player_matches`)
- Экспертная оценка (интервью по анкете `INTERVIEW_EXPERT.md`)

### Блокнот

→ `notebooks/H1_expert_validation.ipynb`

### Ожидаемый вывод

κ ≥ 0.4 — алгоритм адекватно определяет слабые места. κ < 0.2 — требуется пересмотр расчёта фичей.

## H2. Историческая валидация: работает ли методика улучшений

### Формулировка

- **H₀:** Игроки, у которых алгоритм определяет слабые места X, не улучшаются в X быстрее остальных
- **H₁:** Игроки, целенаправленно улучшающие идентифицированные слабые места, показывают рост MMR быстрее baseline

### Метрика

- Для игроков из Kaggle, присутствующих в нескольких временных периодах:
  - **Δ metric** (изменение GPM/XPM/KDA между периодами)
  - **Δ rank_tier** (изменение ранга)
  - Корреляция между «размером gap в период T₁» и «ростом метрики в T₂»
- **Model vs Baseline:**
  - Model: рекомендация фокусировать на top-3 слабых местах
  - Baseline: случайный выбор 3 метрик для улучшения
  - Сравнить средний Δ rank_tier для обеих групп

### Подгипотезы

| ID | Гипотеза | Критерий |
|----|----------|----------|
| H2.1 | Игроки с gap в GPM > 2 показывают рост GPM > 5% | t-test p < 0.05 |
| H2.2 | Рост в идентифицированных слабых местах коррелирует с ростом ранга | ρ > 0.3, p < 0.05 |
| H2.3 | Наша система идентификации > random baseline | paired t-test |

### Источник данных

- `ml_raw_players` — игроки, появляющиеся в матчах разных месяцев
- Псевдо-панельные данные: один account_id → метрики в T₁ и T₂

### Блокнот

→ `notebooks/H2_historical_improvement.ipynb`

### Ожидаемый вывод

Если корреляция подтверждается: методика рабочая — определённые слабые места действительно являются точками роста.

## H3. Продуктовая метрика: помогает ли сервис принимать решения

### Формулировка

- **H₀:** Наличие подробной статистики и обоснованного подбора тренера не влияет на конверсию (решение нанять тренера)
- **H₁:** Игроки, видящие конкретные слабые места и обоснованный подбор тренера, чаще принимают решение о найме

### Метрика

- **CR (Conversion Rate):** доля игроков, перешедших от просмотра профиля к заявке тренеру
- **Time to Decision:** время от привязки Steam до первой заявки
- **Engagement Score:** сколько разделов открыл игрок (Dashboard, Stats, Coaches, AI Chat)
- **Feature Value Score:** пользователи оценивают полезность каждого раздела (1–5)

### Подгипотезы

| ID | Гипотеза | Критерий |
|----|----------|----------|
| H3.1 | Игроки с привязанным Steam более вовлечены | sessions_linked > sessions_not_linked, p < 0.05 |
| H3.2 | Персонализированные рекомендации повышают CR | CR_personal > CR_generic × 1.2 |
| H3.3 | AI-советы увеличивают retention | DAU_with_ai > DAU_without_ai |

### Источник данных

- Логи сервиса (API requests) — можно собрать через middleware
- Опрос пользователей (5 вопросов по Likert scale)

### Блокнот

→ `notebooks/H3_product_metrics.ipynb` (framework + симуляция на доступных данных)

### Ожидаемый вывод

Определяет Product-Market Fit: если игроки с детальным анализом конвертируются лучше, сервис создаёт ценность.

## H4. (Будущее) Качество AI-советов

> Не реализуется на текущем этапе. Потребует полноценной LLM.

- **H₀:** AI-советы не точнее случайных советов
- **H₁:** AI-советы совпадают с экспертными рекомендациями в ≥ 50% случаев

## H5. (Дополнительная) Точность MMR-оценки

### Формулировка

- **H₀:** Наша эвристическая формула MMR не точнее случайного предсказания
- **H₁:** Эвристика MMR имеет MAE < 500 MMR для игроков с известным rank_tier

### Метрика

- MAE (Mean Absolute Error) между estimated_mmr и реальным rank_tier → mmr_mapping
- Сравнение с baseline: «всем присвоить средний MMR»
- Проверка на Kaggle-данных (369K записей с rank_tier)

### Блокнот

→ Включён в `notebooks/H0_feature_quality.ipynb` (секция 4)
