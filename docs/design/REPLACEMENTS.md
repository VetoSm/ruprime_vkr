# Замены и пропуски при переносе макетов в продакшен фронт

Этот документ — **обязательное правило** для любого AI/разработчика, который собирает страницы по PNG из `docs/design/mockups/`.

Принцип: **на макете есть всё, но в проде используем только то, для чего есть бэк**. Недостающие визуальные элементы попадают в `TOOLKIT.md` (как зарезервированные ассеты для будущего), но в страницы не вставляются. Если убираем элемент — **не оставляем пустое место**, а пересобираем композицию (центруем, расширяем оставшиеся блоки и т.п.).

---

## Глобальные правила замен

### 1. Авторизация / OAuth

| На макете | В прод | Действие |
|---|---|---|
| Кнопка "Войти через Discord" | — | **Убрать.** Кнопку "Войти через Steam" центрировать, занять всю ширину блока социальных провайдеров. Иконка Discord → в toolkit, неактивна. |
| Кнопка "Войти через Steam" | `GET /auth/steam/login` | **Использовать как primary auth.** |
| Email+пароль форма | `POST /auth/login`, `/register` | **Оставить ниже Steam-кнопки**, разделитель "или почтой". |
| Регистрация: переключатель "Я игрок / Я тренер" | `POST /auth/register` с role | **Оставить.** Игрок создаётся как PLAYER; "Я тренер" = `coach_application_status=PENDING`. |
| 2FA / Двухфакторная аутентификация | — | **Убрать toggle** из настроек безопасности. Иконка щита → в toolkit. |
| "Сессии в Discord" toggle | — | **Убрать.** |

### 2. Платежи / монетизация

| На макете | В прод | Действие |
|---|---|---|

| "Выплатить" кнопка в кабинете тренера | — | **Убрать.** Заменить на "Сводка месяца" → ссылка на список сессий. |
| "Гарантии: возврат средств, MMR-челлендж" | — | **Убрать блок.** Заменить на "Что включает сессия" (Анализ матча / Лайв-обучение / План тренировок) — уже есть. |
| "Подписка Pro · до 12.06.26" блок в профиле | — | **Убрать.** Иконка короны → в toolkit. |
| "Оплатить", "Платежи", "Биллинг" пункты меню | — | **Убрать из навигации.** |

### 3. Меню и навигация

Sidebar строится **только из реальных роутов** `services/frontend/src/App.tsx`:

**Игрок (`PLAYER`):**
- `/dashboard` — Обзор
- `/stats` — Аналитика
- `/schedule` — Расписание / тренировки
- `/coaches` — Тренеры
- `/requests` — Сессии и заявки
- `/ai-chat` — Оракул
- `/settings` — Настройки

**Тренер (`COACH`):**
- `/coach/dashboard` — Обзор
- `/coach/schedule` — Расписание
- `/coach/profile` — Профиль тренера
- `/coach/reviews` — Отзывы
- `/stats` — Аналитика (общая со студентами)
- `/ai-chat` — Оракул
- `/settings` — Настройки

**Не добавляем** пункты, которые встречаются на разных PNG, но **роутов нет**:
- ❌ Курсы / Обучение / Гайды
- ❌ Мета / Герои / Рейтинги
- ❌ Сообщество / Блог / Поддержка
- ❌ Сообщения / Чат
- ❌ Уведомления (как отдельная страница; колокольчик в topbar — оставить, ведёт в выпадашку)
- ❌ Цели (как отдельная страница; виджет на дашборде — оставить, если без CRUD)
- ❌ Разборы матчей / Реплеи (как отдельный пункт)
- ❌ Платежи / Финансы / Тарифы
- ❌ Уведомления (страница)
- ❌ Реферальная программа
- ❌ Промокоды
- ❌ Поиск тренера (как отдельный пункт — это и есть `/coaches`)

Все эти иконки/название → в toolkit как `nav-item-future`, в actual `<Sidebar>` не подключаются.

### 16. Аватары и иконки героев

**Принцип:** там, где речь о **пользователе** (игрок, тренер, ученик) — используем Steam avatar; там, где речь о **герое или предмете Dota** — используем картинку из opendota CDN.

**Никогда не подставляем сгенерированные на PNG лица как реальные аватары пользователей.** На макетах они — декор. В проде они подменяются на реальные источники.

#### Источники изображений

| Что | Источник | Где взять |
|---|---|---|
| Аватар игрока (свой, чужой) | Steam через OpenDota | `summary.avatar_url` из `GET /player/{id}/stats/overview` или `acc.avatar_url` из `GET /player/steam-data` (`/ml/player-account/{dota_account_id}` бэкенд-сторона). Это CDN-ссылка Steam (`https://avatars.akamai.steamstatic.com/...`). |
| Аватар тренера | Steam (если привязан) | тренеры — это `CoachProfile`, у каждого есть `core_user_id` → `PlayerProfile` той же CoreUser → `dota_account_id` → `/ml/player-account/{dota_account_id}` → `avatar_url`. На фронте делать через хук `useCoachAvatar(coachProfileId)` или запрос через `coreApi.get('/ml/player-account/{aid}')`. |
| Аватар без linked Steam | placeholder | `<Avatar />` рендерит initials (первые 2 буквы login) на cyan-violet gradient. Никакой выдуманной картинки. |
| Иконка героя | OpenDota CDN | `heroIcon(heroId)` из `services/frontend/src/api/heroes.ts` → возвращает URL `https://cdn.opendota.com/apps/dota2/images/heroes/{slug}_sb.png`. Перед использованием — `await loadHeroes()`. |
| Иконка предмета (item) | Valve CDN | `itemIcon(name)` из `api/dota_assets.ts`. URL: `https://cdn.cloudflare.steamstatic.com/apps/dota2/images/dota_react/items/{name}.png`. Использовать в Last matches (опц.) и Oracle chat (если LLM вернёт билд). |
| Иконка способности (ability) | Valve CDN | `abilityIcon(name)` из `api/dota_assets.ts`. URL: `.../abilities/{ability_name}.png`. |
| Иконка ранга (медаль) | inline SVG | `<RankBadge rankTier={...} />` уже есть в `GameComponents.tsx`. |
| Иконки ролей | inline SVG | `<RoleBadge role="POS2" />` уже есть. |
| Аватар "Оракула" (AI) | декоративный градиент | `<OracleOrb />` — purple → cyan gradient circle, без картинки. |

#### Замены по местам

| Место на макете | Замена в проде |

#### Декоративные фоны страниц

> **Стратегия:** используем Hero renders с Valve CDN с low opacity + blur. Helper'ы и пресеты в `services/frontend/src/api/dota_assets.ts` (`decorRender(key)`, `DECORATIVE_HEROES`).

Все декоративные изображения:
- помечаются `aria-hidden="true"`;
- лежат в псевдоэлементах `::before` / `::after` или в отдельных `<div>` с `pointer-events: none`;
- не влияют на ровную работу страницы при недоступности CDN (фолбэк = существующий CSS-gradient).

| Страница | Где декор | Что используем |
|---|---|---|
| **Auth** (`Login`, `Register`) | Левый и правый край hero-section, blur(2-4px), opacity ≤ 0.22 | `decorRender('auth.left')` = Invoker, `decorRender('auth.right')` = Lina |
| **404 NotFound** | Большой силуэт за цифрами "404", opacity 0.22, mix-blend-mode `screen` | `decorRender('notfound.center')` = Vengeful Spirit |
| **Dashboard** (player AppLayout) | Нижний угол sidebar'а, mask-image `linear-gradient(to top, black, transparent)`, opacity 0.35 | `decorRender('dashboardCorner')` = Invoker |
| **Coach Dashboard / Coach Landing** | Левый/правый бок hero-section | `decorRender('coachLanding.left')` = Rubick, `decorRender('coachLanding.right')` = Oracle |
| **Landing** | Не используем — превью самодостаточно (sparkline, skill rings, mini-avatar placeholder) | — |
| **Coach Profile**, **Coaches list**, **Stats**, **Schedule**, **Sessions**, **Oracle Chat**, **Player Profile** | Без декора, только базовый radial-gradient из `theme.css` | — |

**Если хочется поменять конкретного героя для декора** — это **одна правка** в `DECORATIVE_HEROES` константе `dota_assets.ts`. Все страницы подхватят автоматически.

#### Кэширование и lazy-loading

1. **Hero metadata** — загружается один раз: вызывать `await loadHeroes()` в `App.tsx` на маунте или в `<AuthProvider>` после login. Кеш живёт в модуле `api/heroes.ts`.
2. **Steam avatars** — браузер кеширует естественно (Cache-Control от Steam CDN). Для тренеров — кешировать в react-query / SWR с TTL ~1 час, чтобы не делать N запросов на каждую перерисовку каталога.
3. **Fallback** на ошибку загрузки картинки — `onError` → подменяем на `<Avatar variant="placeholder">` с инициалами.

#### Компоненты для toolkit

В `services/frontend/src/ui/data/`:

- `<Avatar src={url} fallbackText="SB" size={88} variant="default|player|coach|student" />` — общий компонент аватара с onError-фолбэком. Шапка кругом + cyan border + опц. online dot (НЕ показываем — см. §7) + опц. rank badge оверлей в углу.
- `<HeroIcon heroId={1} size={28} showName />` — уже есть в `GameComponents.tsx`, переиспользуем.
- `<HeroChip heroId={1} size="sm|md" />` — wrapper над HeroIcon в pill-форме с заполнением (см. `.coach-hero-chip` в `theme.css`).
- `<CoachAvatar coachProfileId={123} fallbackName="Eclipse" />` — хук + render, тянет `dota_account_id` через `useCoachSteam(coachProfileId)`. Возвращает `<Avatar />`.
- `<PlayerAvatar playerProfileId={123} fallbackName="ShadowBlade" />` — аналогично, для учеников/собственного аккаунта.

## Принцип "не оставляем пустоту"

Если из макета убирается элемент — **композиция переcобирается**, чтобы страница не выглядела дырявой:

- Убрали Discord-кнопку → Steam-кнопка по центру, full-width.
- Убрали "Доход" KPI → KPI-row из 3 карточек вместо 4 (или подставить "Часы коучинга").

- Убрали правую колонку с "Подсказками" → main content расширяется на всю ширину.
- Убрали tab → tabs-row пересчитывает оставшиеся.

Это всегда явно отмечается в соответствующем `pages/<page>.md` в секции `Composition`.
