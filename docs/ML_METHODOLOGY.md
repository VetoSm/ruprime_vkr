## 2. Источники данных

| `net_worth` | Нетворс на момент конца | ✓ всегда |

**Что:** данные конкретного привязанного игрока.

| Эндпоинт | Что возвращает | Кол-во данных |

| `/players/{id}/wl` | Побед/поражений за всё время | 2 числа |

| `/players/{id}/recentMatches` | Последние 20 матчей с полными данными | 20 матчей |

| `/players/{id}/heroes` | Статистика по героям (games, win) | все герои |
| `/players/{id}/rankings` | Перцентиль по каждому герою (percent_rank) | все герои |

- `/matches` (пагинированный) — нет GPM/XPM/damage (только K/D/A, duration, hero)

- `/totals` — средние за ВСЮ жизнь (4000+ игр), не разделяются по ролям/героям
- Некоторые поля (stuns, wards, APM) доступны только для ~3% матчей (parsed matches)
- Rate limit: 60 запросов/мин

## 3. Расчёт эталонов (Baselines)

### 3.1. Текущий алгоритм

```python
# Группировка: (mmr_band, hero_id, lane_role)
# Агрегация: AVG по каждой метрике
# Фильтр: match_count >= 5

SELECT mmr_band, hero_id, lane_role,
       AVG(gpm), AVG(xpm), AVG(kda), AVG(kills), AVG(deaths),
       AVG(last_hits), AVG(denies), AVG(hero_damage), AVG(tower_damage),
       AVG(winrate), COUNT(*) as match_count
FROM (kaggle_players JOIN kaggle_matches)
GROUP BY (mmr_band, hero_id, lane_role)
HAVING match_count >= 5
```

**MMR-бэнды (текущие):**

| Бэнд | rank_tier | Медали | Примерный MMR |
|-------|-----------|--------|---------------|
| 0-2000 | 0-39 | Herald, Guardian, Crusader | 0-2300 |
| 2000-4000 | 40-59 | Archon, Legend | 2300-4600 |
| 4000-6000 | 60-79 | Ancient, Divine | 4600-5600 |
| 6000+ | 80+ | Immortal | 5600+ |

**Проблема:** Бэнды слишком широкие. Herald (500 MMR) и Crusader (2200 MMR) в одном бэнде — их стиль игры сильно отличается.

### 3.2. Текущие показатели эталонов

| Метрика | 0-2000 | 2000-4000 | 4000-6000 | 6000+ | Рост |
|---------|--------|-----------|-----------|-------|------|
| GPM | 360 | 408 | 439 | 498 | +38% |
| XPM | 442 | 487 | 525 | 590 | +33% |
| KDA | 4.38 | 4.83 | 4.92 | 5.48 | +25% |
| Kills | 4.82 | 5.07 | 5.15 | 5.39 | +12% |
| Deaths | 4.19 | 4.33 | 4.33 | 4.30 | +3% |
| Last Hits | 135 | 148 | 150 | 172 | +27% |
| Hero Damage | 14,245 | 16,012 | 16,587 | 17,958 | +26% |
| Tower Damage | 1,682 | 1,903 | 1,831 | 2,258 | +34% |

**Наблюдения:**
- GPM и Tower Damage растут сильнее всего (+38%, +34%)
- Deaths почти не меняется (+3%) → на про-уровне все умирают одинаково
- Данные смещены в сторону про-матчей → средние показатели выше типичных паб-игроков

### 3.3. Проблемы текущей системы

1. **Широкие бэнды:** Herald и Crusader в одном — разный стиль игры
2. **Только AVG:** Средние значения скрывают разброс. GPM 360 ± 150 — огромная дисперсия
3. **Нет разделения по позиции:** POS1 (керри) и POS5 (хард саппорт) в одном бэнде с одним героем имеют кардинально разный GPM
4. **Нет временного учёта:** Мета меняется по патчам, а мы берём всё подряд
5. **Нет учёта длительности:** GPM в 25-минутной игре ≠ GPM в 50-минутной
6. **Только про-данные:** Нет данных для Herald-Archon уровня

## 4. Расчёт фичей игрока

### 4.1. Текущие 6 категорий

| # | Категория | Компоненты | Источник данных | Проблемы |
|---|-----------|-----------|-----------------|----------|
| 1 | Фарм и Экономика | GPM, LH/мин, Denies, XPM | totals / detailed matches | XPM дублируется в категории 6 |
| 2 | Боевая эффективность | KDA, Kills, Hero Damage, Assists | totals / detailed matches | Hero damage только из 20 recent |
| 3 | Выживаемость | Deaths (инверсия), Healing, Winrate | totals | Healing = 0 для большинства керри |
| 4 | Картография и Вижн | Obs wards, Sen wards, Total wards | totals (`purchase_ward_*`) | Данные только за 1-3% матчей (parsed) |
| 5 | Инициация и Контроль | Tower damage, Tower kills, Stuns | totals | Stuns данные за ~3% матчей |
| 6 | Ранняя игра | XPM, LH, GPM | totals | Дублирует категорию 1, нет реальных early-game метрик |

### 4.2. Формула score (текущая)

```
score = min(player_value / baseline_value × 5, 10)
```

Где `baseline_value` — среднее по текущему бэнду, `target_value` — среднее по целевому бэнду.

**Проблема:** Деление на среднее (`AVG`) — игрок на уровне среднего получает 5/10. Но "средний" != "хороший". Нужно стремиться к 90-му перцентилю, а не к медиане.

### 4.3. Что НЕ используется, но есть в данных

| Метрика | Где есть | Почему не используется |
|---------|----------|----------------------|
| `camps_stacked` | Kaggle | Нет в OpenDota matches |
| `teamfight_participation` | Kaggle | Нет в OpenDota matches |
| `actions_per_min` | Kaggle + OpenDota totals | Есть в totals, не подтягивается |
| `lane_efficiency_pct` | OpenDota totals | Не подтягивается |
| `neutral_kills` | OpenDota totals | Не подтягивается |
| `pings` | OpenDota totals | Не подтягивается (коммуникация!) |
| `throw/comeback/stomp/loss` | OpenDota totals | Не подтягивается |
| `rankings.percent_rank` | OpenDota per hero | Не используется — а это прямой перцентиль! |
| `histograms` | OpenDota | Распределение GPM по матчам — показывает стабильность |

## 5. Модель MMR

### 5.1. Текущая модель

- **Алгоритм:** GradientBoostingRegressor (sklearn)
- **Обучение на:** `ml_raw_players` (Kaggle, только с `rank_tier > 0`)
- **Записей:** 369,457
- **R² = 0.0845** — ОЧЕНЬ низкий

**Фичи и их важность:**

| Фича | Важность |
|------|----------|
| xp_per_min | 20.6% |
| last_hits | 16.0% |
| actions_per_min | 12.5% |
| kda | 11.2% |
| gold_per_min | 10.8% |
| denies | 7.1% |
| level | 7.0% |
| net_worth | 6.3% |
| tower_damage | 4.9% |
| hero_damage | 3.6% |

### 5.2. Почему R² низкий

1. **Про-данные:** Все игроки 6000+ MMR → минимальная вариация rank_tier
2. **Нет low-rank данных:** Herald, Guardian, Crusader отсутствуют → модель не учится различать
3. **rank_tier = medal, не MMR:** Разница между Divine [1] и Divine [5] = 5 единиц, но 500 MMR
4. **Нет позиционных фичей:** POS5 с GPM 300 и POS1 с GPM 600 — оба Divine, модель путается
5. **Нет hero_id как фичи:** Разные герои = разные нормальные показатели

### 5.3. Альтернативный подход: без ML-модели

Для оценки уровня игрока **не нужна ML-модель**. Достаточно:
1. Взять `average_rank` из последних матчей OpenDota (уже есть!)
2. Или использовать `rank_tier` из профиля OpenDota
3. Или сравнить метрики с baselines через перцентили

ML-модель имеет смысл когда rank_tier неизвестен (закрытый профиль). Но даже тогда heuristic (`composite = 0.3*gpm + 0.2*xpm + 0.3*kda + 0.2*wr`) работает не хуже.

### 6.2. Улучшение эталонов

**A. Использовать перцентили вместо средних (приоритет: ВЫСОКИЙ)**

```
Текущий:  baseline = AVG(gpm)         → "средний" = 5/10
Улучшить: baseline_median = MEDIAN     → 5/10 = типичный
          baseline_p75    = percentile(75)  → 7.5/10 = хороший  
          baseline_p90    = percentile(90)  → 9/10 = отличный
          baseline_top    = percentile(95)  → 10/10 = эталон
```

Так score = player / p90 × 10 — игрок стремится к топ-10%, а не к среднему.

**Реализация:** В `compute_baselines` добавить:
```python
grouped.agg(
    avg_gpm=("gpm", "mean"),
    median_gpm=("gpm", "median"),
    p75_gpm=("gpm", lambda x: x.quantile(0.75)),
    p90_gpm=("gpm", lambda x: x.quantile(0.90)),
)
```

**B. Учитывать позицию (роль) (приоритет: ВЫСОКИЙ)**

Сейчас POS1 и POS5 в одном бэнде сравниваются с одним эталоном. Нужно:
- Baseline для (mmr_band, hero_id, lane_role=1) — керри
- Baseline для (mmr_band, hero_id, lane_role=4) — саппорт

Это уже есть в `lane_role` в baselines, но фичи игрока НЕ разбиваются по ролям.

**C. Учитывать патч/мету (приоритет: СРЕДНИЙ)**

Герои сильно меняются от патча к патчу. Baseline для Invoker в патче 7.37 ≠ 7.38.

### 6.3. Производные фичи

Метрики, которые НЕ тянутся напрямую, но вычисляются:

| Фича | Формула | Что показывает |
|------|---------|----------------|
| **Kill Participation** | (kills + assists) / total_team_kills | Вовлечённость в командные бои |
| **Death Share** | deaths / total_team_deaths | Насколько часто умирает vs команда |
| **Farm Efficiency** | net_worth / (gpm × duration) | Эффективность траты золота |
| **CS/min** | last_hits / duration_min | Скорость фарма (нормализована по времени) |
| **Damage/Gold** | hero_damage / net_worth | Сколько урона выжимает из золота |
| **Objective Focus** | tower_damage / hero_damage | Фокус на объектах vs файтах |
| **Vision Score** | (obs + sen) / duration_min × 10 | Вижн за минуту (нормализован) |
| **Consistency** | std(gpm) / mean(gpm) | Стабильность от матча к матчу |
| **Hero Versatility** | unique_heroes / total_matches | Насколько широкий пул |
| **Clutch Factor** | winrate_long_games - winrate_all | Способность тащить затяжные игры |
| **Comeback Ability** | comeback / (throw + comeback) | Способность камбэчить |
