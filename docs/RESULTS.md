**Практический вывод:** Рекомендация «подтянуть слабейшие метрики» статистически обоснована как лучшая стратегия по сравнению с случайным выбором.

## H5. Точность MMR-оценки

### Методика

Эвристическая формула:
```
gpm_score  = clip((avg_gpm − 300) / 400, 0, 1)
xpm_score  = clip((avg_xpm − 300) / 400, 0, 1)
kda_score  = clip((avg_kda − 1) / 7, 0, 1)
wr_score   = clip((winrate − 0.3) / 0.4, 0, 1)
composite  = 0.3×gpm + 0.2×xpm + 0.3×kda + 0.2×wr
estimated_mmr = 1000 + composite × 8000
```

1. Формула линейная, данные нелинейны

3. Разные роли (POS5 всегда имеет низкий GPM)

## Верификация кода: формулы Score и Gap

### Score = min(player / baseline × 5, 10)

| Сценарий | GPM Score | KDA Score | Deaths Score |
|----------|-----------|-----------|-------------|
| Игрок = baseline | **5.0** ✓ | **5.0** ✓ | **5.0** ✓ |
| Игрок +20% | **6.0** ✓ | **6.0** ✓ | **4.2** ✓ |
| Игрок −20% | **4.0** ✓ | **4.0** ✓ | **6.2** ✓ |
| Игрок ×2 | **10.0** ✓ | **10.0** ✓ | **2.5** ✓ |
| Игрок ×0.5 | **2.5** ✓ | **2.5** ✓ | **10.0** ✓ |

Формула линейная и симметричная. «Средний для ранга» = 5/10 — интуитивно корректно.

### Gap = target_score − current_score (Archon → Divine)

| Метрика | Player | Curr BL | Target BL | Score | Target | Gap |
|---------|--------|---------|-----------|-------|--------|-----|
| GPM | 385.1 | 481.3 | 498.7 | 4.00 | 5.18 | **+1.18** |
| KDA | 3.5 | 4.4 | 4.8 | 4.00 | 5.48 | **+1.48** |
| Last Hits | 138.4 | 173.0 | 173.6 | 4.00 | 5.02 | **+1.02** |

Gap корректно указывает, что KDA — наибольший разрыв для перехода из Archon в Divine.

## Общие выводы и рекомендации

### Что работает

1. **Система фичей валидна** — все ключевые метрики монотонно растут с рангом (ρ > 0.88)
2. **Стратегия «подтянуть слабые» обоснована** — Model > Baseline (p < 0.0001)
3. **Формулы Score и Gap корректны** — линейные, предсказуемые, интуитивные
4. **Полное покрытие аналитики** — 8/8 категорий для parsed-данных, 98–100% героев для Archon+

### Что требует улучшения

| Проблема | Влияние | Приоритет | Решение |
|----------|---------|-----------|---------|
| Перекос данных (82.8% Immortal) | Ненадёжные бейзлайны Herald–Crusader | Высокий | OpenDota Data Dump или массовый сбор parsed-матчей |
| MMR-эвристика MAE=1777 | Неточная оценка ранга | Средний | Использовать rank_tier из OpenDota API |
| Слабая корр. Δmetric ↔ Δrank | Нельзя гарантировать рост ранга | Низкий | Ожидаемо — ранг зависит от множества факторов |
| Vision/Control для OpenDota | 97% непарсенных матчей | Средний | Автозапрос парсинга + fallback |

### Необходимые действия для следующего этапа

1. **H1 (экспертная валидация):** Провести интервью с 5–10 игроками + экспертом по анкете из `docs/INTERVIEW_EXPERT.md`. Данные внести в `notebooks/H1_expert_validation.ipynb`.
2. **Данные:** Расширить базу через OpenDota API/dump для Herald–Ancient рангов.
3. **MMR-оценка:** Перейти на реальный rank_tier из OpenDota или обучить ML-модель с учётом роли.
4. **H3 (продуктовые метрики):** Добавить логирование действий пользователей и провести опрос (анкета в `docs/INTERVIEW_EXPERT.md`, секция 6).
