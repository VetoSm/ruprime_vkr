# Overview

## Назначение

**RuPrime** — платформа для тренировок по Dota 2. Объединяет:

- Аналитику игрового профиля игрока (на основе данных OpenDota и эталонной выборки Kaggle).
- Подбор персонального тренера под цели игрока (роль, ранг, фокус).
- Управление тренировочными сессиями (запись, отмена, перенос, отчёт, отзыв).
- AI-советника для быстрых вопросов по игре (LLM, OpenAI-совместимый провайдер).
- Административную панель: модерация заявок тренеров, управление пользователями, импорт ML-данных.

## Роли пользователей

| Роль   | Описание |
|--------|----------|
| **PLAYER** | Игрок. Может привязать Steam-аккаунт, получить аналитику, искать тренера, общаться с AI-чатом. |
| **COACH**  | Тренер. Заполняет публичную карточку, видит входящие заявки, отчитывается по сессиям. Получает рейтинг по отзывам. |
| **ADMIN**  | Администратор. Подтверждает заявки тренеров, управляет ролями, импортирует датасет, смотрит логи и статистику. |

Регистрация всегда создаёт пользователя с ролью `PLAYER`. Роль `COACH` присваивается только после одобрения заявки админом. Роль `ADMIN` присваивается вручную через БД или через эндпоинт `/auth/admin/users/{id}/role`.

## Основные пользовательские сценарии

### 1. Игрок получает аналитику профиля

1. Регистрируется (email/пароль) или логинится через Steam OpenID.
2. Привязывает Dota-аккаунт через Steam (один раз).
3. `core` инициирует загрузку матчей через `ml` → `ml` тянет данные из OpenDota API.
4. `ml` рассчитывает 8 категорий метрик (фарм, агрессия, виженье и т. д.), сравнивает с baseline по `(MMR-band × hero × role)`.
5. Игрок видит дашборд: сильные стороны, слабые места, прогресс, оценка MMR.

### 2. Игрок ищет тренера

1. Создаёт заявку на тренировку: желаемая роль, фокус (например, «лейн-фаза»).
2. `core` идёт в `ml` за рекомендациями: ранжирование тренеров с учётом совместимости по ролям и MMR.
3. Игрок выбирает тренера → создаётся `TrainingSession`.
4. После тренировки — отчёт от тренера + отзыв от игрока.

### 3. Игрок задаёт вопрос AI-советнику

1. Открывает чат, пишет сообщение.
2. `core` собирает контекст игрока (последние слабые стороны, цели), идёт в `llm`.
3. `llm` обращается к OpenAI-совместимому API (или возвращает шаблонный ответ при отсутствии ключа).
4. Ответ сохраняется в `AiAdviceHistory`.

### 4. Тренер ведёт работу

1. Заполняет `CoachProfile`: ранг, роли, hero pool, ставка, опыт.
2. Видит список запросов на тренировку, принимает/отклоняет.
3. Заполняет отчёт по сессии, видит средний рейтинг от учеников.

### 5. Админ управляет системой

1. Видит общую статистику (пользователи, сессии, активность).
2. Одобряет/отклоняет заявки на роль COACH.
3. Просматривает любые таблицы БД через защищённый просмотрщик.
4. Запускает импорт Kaggle-данных и тренировку MMR-модели.

## Источники данных

- **Kaggle Dataset (Pro League 2024–2025)** — ~594K записей, используется для построения baseline-статистики.
- **OpenDota API** — профиль, матчи, totals игрока в реальном времени.
- **Steam Web API** — резерв для случаев, когда match history скрыт (личные данные, аватар, часы в Dota).
- **OpenAI-совместимый LLM** — генерация советов в чате (опционально, с fallback на шаблоны).
